# MLOps Assignment 6: Containerize an ML Model Using Docker

## 1. Assignment Overview
This project implements **MLOps Assignment 6 – Containerize an ML Model Using Docker**. The objective is to build an end-to-end reproducible machine learning pipeline that packages a trained classification model into a lightweight, isolated Docker container capable of performing on-demand runtime inference via an interactive terminal session.

---

## 2. Aim
To demonstrate the complete MLOps workflow for model containerization:
1. Train a Machine Learning classification model on the Iris dataset using Scikit-Learn.
2. Persist the trained model artifact using Joblib (`model.joblib`).
3. Build a Python inference application (`app.py`) that loads the serialized model and makes predictions on dynamic runtime user inputs.
4. Define minimal, pinned project dependencies in `requirements.txt`.
5. Author a multi-step `Dockerfile` based on an official Python runtime.
6. Build and tag the Docker container image (`iris-ml-model`).
7. Run the container interactively, feed flower feature measurements, and verify accurate predictions.
8. Validate container independence, container lifecycle (`docker ps` / `--rm`), and input validation.

## 5. Model Training Procedure (`train_model.py`)
The training script performs the following steps:
1. **Data Loading**: Loads the classic Fisher's Iris dataset from `sklearn.datasets.load_iris()` containing 150 samples across 3 classes (`setosa`, `versicolor`, `virginica`) and 4 features:
   - Sepal length (cm)
   - Sepal width (cm)
   - Petal length (cm)
   - Petal width (cm)
2. **Train/Test Split**: Partitions the 150 records into an 80% training set (120 samples) and a 20% testing set (30 samples) using `random_state=42`.
3. **Model Selection**: Instantiates a `RandomForestClassifier` with `n_estimators=100` and `random_state=42`.
4. **Model Training**: Fits the ensemble model on `X_train` and `y_train`.
5. **Evaluation**: Evaluates predictions on the held-out `X_test` partition.
   - **Actual Test Accuracy**: `1.0000` (100.00%)
   - **Classification Report**:
     ```text
                   precision    recall  f1-score   support

           setosa       1.00      1.00      1.00        10
       versicolor       1.00      1.00      1.00         9
        virginica       1.00      1.00      1.00        11

         accuracy                           1.00        30
        macro avg       1.00      1.00      1.00        30
     weighted avg       1.00      1.00      1.00        30
     ```
6. **Model Persistence**: Serializes the fitted classifier to `model.joblib` (182.52 KB).

### How to Run Model Training

## 6. Prediction Application (`app.py`)
`app.py` serves as the runtime inference engine:
1. **Model Loading**: Safely loads `model.joblib` into memory. If the model artifact is missing, it exits with an informative error message.
2. **Runtime Input Acquisition**: Accepts input either interactively from terminal standard input (`input()`) or through command-line arguments.
3. **Validation and Parsing**:
   - Parses comma-separated (`5.1, 3.5, 1.4, 0.2`) or whitespace-separated entries.
   - Checks that exactly 4 numerical tokens are provided.
   - Validates that measurements are positive decimal numbers.
4. **Inference Execution**: Reshapes the input into a 2D NumPy array of shape `(1, 4)` and invokes `model.predict()`.
5. **Output Mapping**: Translates predicted integer class indices (`0`, `1`, `2`) to species names (`setosa`, `versicolor`, `virginica`).

### How to Run Locally
```bash
python app.py
```

## 7. `requirements.txt` Explanation
To adhere to production containerization best practices, only packages strictly needed for model deserialization and array manipulation are included:

```text
scikit-learn>=1.5.0
joblib>=1.3.0
numpy>=1.26.0
```

- **scikit-learn**: Required because `RandomForestClassifier` and `DecisionTreeClassifier` classes must be registered during unpickling.
- **joblib**: Required for deserializing `model.joblib`.
- **numpy**: Required to construct and format input feature matrices for inference.

Heavy, unnecessary libraries (e.g. pandas, matplotlib, seaborn, fastapi) are intentionally excluded to keep the container image lightweight.

## 8. Dockerfile Instruction-by-Instruction Breakdown

```dockerfile
# 1. Base Image
FROM python:3.11-slim

# 2. Working Directory
WORKDIR /app

# 3. Copy Dependency Specification
COPY requirements.txt .

# 4. Dependency Installation
RUN pip install --no-cache-dir -r requirements.txt

# 5. Copy Model Artifact & Application Source
COPY model.joblib .
COPY app.py .

# 6. Default Execution Command
CMD ["python", "app.py"]
```

### Detailed Instruction Explanations:
1. `FROM python:3.11-slim`:
   - Specifies the official Python 3.11 minimal base image built on Debian Linux. The `-slim` variant omits unnecessary build tools, keeping base size under ~130 MB while providing a stable, secure runtime.
2. `WORKDIR /app`:
   - Creates and sets `/app` as the primary working directory inside the container for subsequent instructions (`COPY`, `RUN`, `CMD`).
3. `COPY requirements.txt .`:
   - Copies `requirements.txt` from host build context into `/app/` inside the image layer. Placed before copying application code to leverage Docker layer caching.
4. `RUN pip install --no-cache-dir -r requirements.txt`:
   - Installs the required Python packages into the container environment. The `--no-cache-dir` flag prevents caching downloaded wheel files in `/root/.cache`, reducing the final image size.
5. `COPY model.joblib .` and `COPY app.py .`:
   - Copies the serialized model weights and inference source code into `/app/`.
6. `CMD ["python", "app.py"]`:
   - Specifies the default executable command executed when the container starts. Can be overridden if needed (e.g. `docker run -it iris-ml-model bash`).

## 10. Container Execution Commands

Run the container interactively:
```bash
docker run --rm -it iris-ml-model
```

### Flags Breakdown:
- `--rm`: Automatically removes the container filesystem when it terminates, preventing stale stopped containers from consuming disk space.
- `-i` (`--interactive`): Keeps STDIN open so the container can accept input from the user's keyboard.
- `-t` (`--tty`): Allocates a pseudo-TTY terminal for formatted terminal output and interactive prompts.

### Non-Interactive / Piped Execution:
```bash
echo "5.1, 3.5, 1.4, 0.2" | docker run --rm -i iris-ml-model
```

## 11. Verification and Container Inspection

### Container List Verification:
```bash
docker ps
```

### Understanding `--rm` Behavior:
Because the prediction container is run with `--rm`, Docker automatically destroys the container immediately upon process exit. Running `docker ps` after the prediction finishes will show an empty list (or other unrelated containers), which is the **expected and correct behavior of an ephemeral batch container**.

### Demonstrating a Running Container with `docker ps`:
To visually verify a running container using `docker ps`, run a temporary detached container:
```bash
# 1. Start a temporary background container
docker run -d --name iris-verification-demo iris-ml-model sleep 30

# 2. Inspect active container list
docker ps

# 3. Clean up the demonstration container
docker rm -f iris-verification-demo
```

## 13. Troubleshooting Instructions

| Issue | Cause | Solution |
| :--- | :--- | :--- |
| `failed to connect to docker API at npipe` | Docker Desktop is not running or initializing on Windows. | Launch Docker Desktop from the Start Menu, wait until the whale icon in the taskbar turns solid green, and verify with `docker info`. |
| `FileNotFoundError: model.joblib` | The model has not been trained prior to container build or running inference. | Run `python train_model.py` to generate `model.joblib`, then re-run `docker build -t iris-ml-model .`. |
| `the input device is not a TTY` | Running `docker run -it` inside non-interactive automation shells. | Use `docker run -i` without `-t`, or pipe input directly: `echo "5.1, 3.5, 1.4, 0.2" \| docker run --rm -i iris-ml-model`. |
| Missing packages during build | Network timeout during wheel download. | Re-run `docker build -t iris-ml-model .`. Docker caches successfully built layers and resumes seamlessly. |
